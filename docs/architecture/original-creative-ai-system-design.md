# 원본 창작 AI 시스템 설계 (Original Creative-AI System Design)

> **상태**: DRAFT (검토 대기) · 2026-06-29 작성
> **동기**: 사용자 비전 — 남의 그림체를 빌리지 않고 **나만의 원본 그림체를 학습으로 형성**하고,
> 그 스타일로 **이미지 생성**하며, 나아가 **애니메이션/영상**까지 만드는 통합 창작 시스템.
> **선행 맥락**: Live2D 루프 리깅이 단일 일러 천장(seam·멀티포즈 불가) 도달
> ([[reference_2d_rigging_automation_landscape]]) → AI 영상 자가호스트 정찰 결과
> "anime 자가호스트 모델 없음"([[reference_talking_head_lipsync_landscape]] 갱신 예정) →
> **우리만의 파이프라인을 직접 구축** 결정. 단 from-scratch 학습은 데이터·컴퓨트 불가이므로
> **계층별로 학습(스타일) vs 조합/파이프라인(이미지·영상)을 배치**.

## 0. 3+1 합의 반영 (REVISE, 2026-06-29) — 구속력 있는 정정

> 합의 보고서: `docs/review/3plus1-consensus-2026-06-29-original-creative-ai-system.md`.
> 아래는 본문(§1~§9)에 우선하는 정정. (조건부 통과 / REVISE)

- **R-1 프레이밍 정직화**: "RLHF-lite/강화학습/원본"은 over-claim. 실제 = **선호 큐레이션
  best-of-N SFT**(후보→pick→pick으로 LoRA fine-tune. 보상모델·정책 그래디언트 없음, RL 아님)
  + **prior 위 고유 수렴**. "원본"=무에서 신규 화풍이 아니라 *사용자 선호로 수렴·결정화된 고유
  스타일*. **수렴이 특정 작가 시그니처에 근접할 수 있음**(베이스 prior 상속) — 정직 명기.
- **R-2 ② 다중 LoRA 정정**: 현 gen_gate는 **단일 LoRA 슬롯**(`gate.py`·`_apply_lora` unload-
  then-load). 스타일+캐릭터 동시 = **신규 multi-adapter 코드(`set_adapters`)+간섭 튜닝(ZipLoRA)
  필요** (="기존 지원/신규 코드 최소" 거짓). 영상(③) 보존은 *스타일 입력 이미지 조건화*이지
  SDXL my-style LoRA 재적재 불가(영상 모델 아키텍처 상이).
- **R-3 ③ 범위 축소 + 오디오 현실화**: ③의 정당화 = **Live2D가 못하는 것(진짜 head-turn·멀티
  포즈·씬 모션) 돌파만**. talking-head/립싱크는 **motion_lab 2D로 흡수**(viseme/2.5D/THA3 대안은
  *모두 Live2D 천장 재생산*). 오디오→I2V 조건화 = **연구급**(2D 리그 모션→diffusion latent 다리
  발명 필요, cheap PoC 불가) → "경량 어댑터" 철회, **P4+ 별도 연구 트랙**. ③은 **병렬 스파이크로
  강등**(핵심 가치 비게이팅).
- **R-4 순서 반전**: **P1(스타일)→P2 우선**, P0(영상 HW)는 **병렬 timebox·비게이팅**.
- **R-5 다중 스타일**: **MVP = 명시(Explicit) 트랙**. 자동 클러스터링은 후속(CLIP는 *내용*으로
  군집→스타일 분리엔 style-specific 임베딩 필요·콜드스타트 노이즈).
- **R-6 ① 보강**: ⓐ**dislike(거부) 신호 회수**(→ 후속 **DPO**로 정식 선호 최적화) ⓑ**무학습
  콜드스타트**(IP-Adapter로 수렴 전 LoRA 재학습 비용 회피) ⓒ**정량 수렴 센서**(고정 프롬프트셋
  CLIP/Gram 자기일관성 — "vibes 수렴" 차단, 계산적 검증 우선) ⓓ**매 라운드 base에서 누적 코퍼스
  전체 재학습**(이어학습 금지, 드리프트 회피) ⓔ**본인 그림 학습(경로 b)을 선택 트랙으로 스케줄**
  (유일한 진짜 from-scratch 원본).
- **R-7 라이선스**: 상업 트랙 코퍼스에서 **개인전용 베이스(noobai) 제외** 또는 등급 전파 규칙
  명문화(gen_gate 등급 게이트 정렬). ③ 영상 모델 **영토 라이선스 선검증(0-C)**(Hunyuan 한국 배제
  전례).
- **R-8 게이트 정량화 + 뿔/날개 drift**: 각 게이트에 객관 기준(0-B=소스 대비 스타일 유사도 임계·
  **비인간 해부(뿔/날개) drift 명시 평가**, P1=홀드아웃 스타일 일관성/블라인드 A/B>chance).

## 1. 핵심 결정 — 방식 배치 (파이프라인 vs 학습)

사용자 질문("여러 모델 합친 파이프라인 vs RL 모델")의 객관적 답 = **계층별로 다르다**:

| 계층 | 방식 | 근거 | 실현성 |
|------|------|------|--------|
| **① 그림체(Style Forge)** | **학습 — 선호 진화(RLHF-lite)** | 스타일은 데이터·취향에서 *학습*되는 것 | ✅ LoRA + 선호 루프(우리 인프라) |
| **② 이미지 생성** | **조합** (gen_gate + ① 스타일 LoRA) | 이미 구축됨 | ✅ ①을 "탐" |
| **③ 애니/영상** | **파이프라인** (사전학습 I2V + 오디오 조건화 + 경량 어댑터) | 프로 방식(Hallo3/OmniHuman도 사전학습 베이스+학습 어댑터) | ⚠️ HW 검증 선결 |

**불가 판정**: 영상 디퓨전 from-scratch 학습 / 전면 RL(데이터 0·GB10 1노드). → ③은 사전학습 조합.

## 2. 아키텍처 (3계층)

```
┌─────────────────────────────────────────────────────────────┐
│ ① STYLE FORGE  — 나만의 원본 그림체*들* (선호 진화 + 다중 라이브러리) │
│   후보→평가(보상)→선호본 누적→스타일 LoRA 학습→재생성→수렴   │
│   스타일별 *독립 트랙*(명시 or 자동 클러스터). 산출 = 스타일  │
│   라이브러리 {my-style-A, B, ...} (각 LoRA·버전관리)         │
└───────────────┬─────────────────────────────────────────────┘
                │ 선택된 my-style LoRA (프로젝트별 바인딩)
                ▼
┌─────────────────────────────────────────────────────────────┐
│ ② IMAGE GEN  — gen_gate가 my-style LoRA를 "탐"               │
│   (베이스모델 + my-style LoRA + 캐릭터 LoRA + 스타일/키워드)  │
│   산출 = 내 스타일의 캐릭터/장면 이미지                       │
└───────────────┬─────────────────────────────────────────────┘
                │ style-consistent images
                ▼
┌─────────────────────────────────────────────────────────────┐
│ ③ ANIMATION  — 사전학습 I2V + 오디오 조건화 파이프라인       │
│   image→video(CogVideoX/Wan) + 립싱크 + 정체성/스타일 보존  │
│   (옵션) Live2D 렌더로 audio-motion 어댑터 *경량* 학습       │
│   산출 = 내 스타일로 말하고 움직이는 캐릭터 영상             │
└─────────────────────────────────────────────────────────────┘
```

## 3. 계층 ① Style Forge — 선호 진화 + **다중 스타일 라이브러리** (핵심 신규)

**목표**: 사용자의 *고유* 그림체(들)를 LoRA로 결정화. RLHF-lite — **사람 선호 = 보상,
LoRA fine-tune = 정책 갱신**. ⭐ **그림체는 하나가 아니라 여럿일 수 있다** → 단일 수렴이 아니라
**스타일 라이브러리**(스타일별 독립 트랙)로 설계. 하나로 평균내면 mush(흐릿)가 되므로 **분리**가 원칙.

### 3.1 루프 (한 스타일 트랙, 한 라운드)
1. **후보 생성**: N장(예 8~12). 스타일 축 변주(베이스모델·스타일 프리셋·LoRA 믹스·샘플러/
   파라미터·키워드). 콜드스타트 = 기존 anime 베이스(animagine/illustrious/noobai)에서 시작
   ([[reference_anime_base_models]]).
2. **선호 평가**: 사용자가 pick/점수(보상). UI(prompt_lab webapp 확장).
3. **선호본 누적**: 상위 선택본 → *해당 스타일의* 선호 코퍼스. 메타(선호된 축) 기록.
4. **스타일 LoRA 학습**: 그 코퍼스로 LoRA 학습/갱신(OneTrainer/lora_lab aarch64 실증
   [[project_base_model_training_alternatives]]). 캐릭터 아니라 *스타일* 학습.
5. **재생성·수렴**: 새 LoRA로 재생성 → 반복 → 그 트랙이 일관 수렴 = "내 스타일 X".

### 3.2 다중 스타일 — 두 모드
- **명시(Explicit) 트랙**: 사용자가 스타일 선언(A/B/…) → 각자 **독립 코퍼스+독립 LoRA**.
  평가 시 "A / B / 새 스타일"로 라우팅.
- ⭐ **창발(Emergent) 클러스터링**(스마트 기본): 사용자는 *좋아하는 것만* 평가 → 선호 이미지를
  **임베딩 클러스터링**해 *서로 다른 스타일 패밀리*를 **자동 발견** → 패밀리당 LoRA 1개. 몇 개인지
  미리 안 정해도 "내 취향이 사실 N가지"를 시스템이 찾음. 명시 라벨로 override 가능.

### 3.3 라이브러리 운영 / 산출
- 각 스타일 = `my-style-<name>-vN` LoRA + 메타(코퍼스·축·수렴 지표). **gen_gate LoRA
  레지스트리에 전부 등록**(다중 LoRA 기존 지원).
- **선택**: 생성/프로젝트마다 스타일 고름(② 4축에 *스타일 축* 합류). 프로젝트(만화·영상)는
  스타일 1개에 바인딩.
- **트랙 운영**: merge/split(코퍼스 조작)·버전관리. **트랙 비혼합 학습 → mush 방지**.
- ⚠️ **블렌딩(스타일 섞기)은 고급**: 2 LoRA 단순 합산 실패(ZipLoRA
  [[reference_lora_attribute_disentanglement]])→순차/전용 기법. MVP=선택만, 블렌딩 후속.

### 3.4 정직한 한계/오픈 질문
- **콜드스타트 파생성**: 초기 후보는 기존 prior → 수렴 *전엔* 남의 스타일 잔존. "원본"=from-scratch
  신규 화풍이 아니라 **사용자 선호로 수렴·결정화된 고유 조합**(prior 위 형성). 진짜 novel은 본인
  그림 학습(경로 b)이 강함.
- **수렴 vs mush**: 트랙 분리·코퍼스 품질이 관건. 클러스터링 품질이 다중 스타일 자동 발견의 핵심.
- **소수 데이터 LoRA**: 선호본 적을 때 과적합/단조 — 정규화·점진 누적·트랙 최소 샘플 임계.

## 4. 계층 ② Image Gen — 기존 자산 재사용

- **gen_gate**([[project_gen_gate]])가 `my-style LoRA`를 일반 LoRA로 적재(레지스트리·트리거·
  베이스 잠금 기존 메커니즘). 4축(내용·베이스·룩프리셋·캐릭터)에 **스타일 축 추가**
  ([[project_uncensored_text_to_image_pipeline]] 4축 통찰 확장).
- 캐릭터 LoRA(예 aveline)와 my-style LoRA **동시 적용**(스타일+캐릭터 분리, 순차 Pivotal 주의
  [[reference_lora_attribute_disentanglement]]).
- 신규 코드 최소 — gen_gate는 이미 LoRA 조합 지원.

## 5. 계층 ③ Animation — 사전학습 파이프라인

### 5.1 단계
1. **I2V 베이스**(image→video): CogVideoX-5B-I2V(diffusers 네이티브·SDPA) 또는 Wan2.x.
   ②의 스타일 이미지를 모션화.
2. **정체성/스타일 보존**: my-style LoRA·reference·IP-Adapter로 on-model 유지.
3. **오디오 조건화**(립싱크) = 가장 novel·난제. 후속.
4. (옵션) **경량 audio-motion 어댑터 학습**: ⭐**Live2D/THA3 렌더로 학습쌍 부트스트랩**
   (audio→우리 리그 모션→영상). from-scratch 아닌 *light* 어댑터.

### 5.2 Phase 0 게이트 (선결, 싸게)
- **0-A HW**: 오픈 I2V가 **GB10 sm_121에서 추론되는가?** ⚠️ 진행중 — CogVideoX 다운로드 OK,
  단 **transformers 5.0이 T5 토크나이저 깨뜨림** → **전용 venv(transformers 4.x) 필요**(첫 과제).
  (LTX-Video는 sm_121 커널 미해결 — CogVideoX는 SDPA라 회피 기대.)
- **0-B 정체성**: I2V가 anime 화풍·정체성 유지 vs 실사 drift? (정찰=실사 학습이라 리스크.)

## 7. 메모리/오케스트레이션 정책 (GB10 121GB 공유)

- **Claude가 빌드 구동, 자비스(로컬 LLM) 보류** — 영상 모델/학습 동시 시 OOM(사용자 지시).
- **단계 순차 실행 + 사이 메모리 해제**(통합 거대 모델 회피 = 파이프라인 선택의 부수 이점).
- gpu flock 준수. 영상 모델 전용 venv 격리.

## 8. 단계적 로드맵 (PoC 게이트 정신)

| Phase | 내용 | 게이트 |
|-------|------|--------|
| **P0** | ③ 영상 베이스 0-A(전용 venv→GB10 추론)+0-B(anime 정체성) | I2V 자가호스트 가부 |
| **P1** | ① Style Forge MVP(1라운드: 후보 생성→평가→LoRA 학습→재생성) | 선호 수렴 신호 |
| **P2** | ② gen_gate에 my-style LoRA 통합(스타일 축) | 내 스타일 이미지 |
| **P3** | ③ 영상 파이프라인(I2V+정체성)→오디오 조건화 | 내 스타일 영상 |
| **P4** | (옵션) audio-motion 경량 어댑터(Live2D 부트스트랩) | 자연 립싱크 |

P0(영상)와 P1(스타일)은 독립 → 병렬 가능. **P1(Style Forge)이 사용자 비전의 진짜 핵심**.

## 9. 정직한 종합 / 결정 필요
