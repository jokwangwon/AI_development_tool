## 7. 추가 위험 / 누락 영역

### 7.1 ADR-011 조건 명칭 불일치

가장 중요한 수정 후보는 “ADR-011 §2.1 (a)~(e)” 표현이다. 원문 불일치가 남으면 후속 합의에서 권위 chain이 흔들릴 수 있다.

**권고:** “ADR-011 §2.1 (a)~(d) + 합의 APPROVE 운영조건 (e)”로 정리.

### 7.2 PC-1 의무화의 실제 강제력

`pre-commit install`은 로컬 개발자 환경에서 우회 가능하다. PC-1 “의무화”가 실제 보안 효과를 가지려면 AR-3/CI에서 동일 hook 결과를 검증해야 한다.

**권고:** PC-1 단독 보안 결과가 아니라 “PC-1 + PC-3 + AR-3 결합 시 의무화 효과”로 표현.

### 7.3 AR-3 required checks mapping

“11 workflow 모두 required status check”는 GitHub UI/API에서 check 이름이 job 단위로 노출되는 문제와 맞물린다.

**권고:** 실 구현 sub-cycle에서 required check 목록을 workflow file명 기준이 아니라 실제 check name 기준으로 evidence화.

### 7.4 ST-2 failure mode

inotify sidecar가 secret file event를 감지해 메인 컨테이너를 정지시키는 방식은 권한, PID namespace, docker-compose healthcheck, restart policy에 따라 다르게 동작한다.

**권고:** ST-2 evidence에 “event 감지”뿐 아니라 “메인 workload fail-closed 확인”을 포함.

### 7.5 S-3 plugin allowlist의 정확한 이름

“ AWS / Generic / Base64 ”는 방향은 맞지만 detect-secrets의 실제 plugin 이름/옵션과 일치해야 한다.

**권고:** 실 구현 sub-cycle에서 allowlist를 detect-secrets CLI가 인식하는 정확한 plugin identifier로 고정하고, `--baseline` 미사용 assertion을 CI에서 검사.
