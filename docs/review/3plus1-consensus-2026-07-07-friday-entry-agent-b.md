### 2. 핵심 발견

1. **[CRITICAL] §4 5-layer 격리는 전부 "프라이데이 *워커*" 격리다. ### 3. 4 invariant 보존 검증 (특히 ① 레이어 Provider Liquidity 정합)

**정면 답변 — ① 레이어는 Provider Liquidity 위반인가?: 현 문면으로는 "잠재 위반", 두 가지 조건 충족 시 "정합".**

ADR-011 §2.1 수단/목적 분리를 5조-2에 적용하면, 5조-2의 본질(목적)은 "**시스템(런타임)이** 모델/구독/오케스트레이터 교체를 코드 변경 없이 감당하는 것"이다. Claude Code가 자비스를 *개발*해온 것이 5조-2 위반이 아니었던 것과 같은 논리로, ① 레이어를 **개발 하네스**로 분류하면 위반이 아니다. ② 레이어(로컬 Ollama)가 런타임 두뇌인 구조는 오히려 5조-2 준수의 교과서적 형태다.

그러나 자가진화 툴에서는 이 분류가 자동으로 성립하지 않는다. **진화 루프가 "개발기 한정"이 아니라 운영 중 상시 기능이 되는 순간, ① 레이어는 개발 도구가 아니라 시스템의 상시 구성요소가 되고, "프라이데이의 진화 능력"이 Claude Code 없이는 정지하는 기능적 락인이 성립한다.** 표어 "Claude가 키우고 프라이데이는 로컬로 자란다"는 양육기/성장기 구분을 암시하지만 brief에 그 경계 조건이 없다. 정합 조건 2가지:

- **(가) 스코프 명문화**: "5조-2 스코프 = 런타임 시스템 구성요소. ① 레이어 = 개발 하네스로 분류, 프라이데이 *제품 정의*에서 제외. 단 진화 루프가 배포 후 상시 기능으로 전환되는 시점 = 재분류 + 별도 합의 의무" — 합의 보고서 또는 ADR 조항으로.
- **(나) Exit ramp 실증 의무**: 진화 루프 정의(관찰→제안→검증 워크플로우)를 provider-중립 스펙(markdown/YAML)으로 유지하고 Claude Code는 *실행기*로만 — 다른 실행기(codex 등, 24번째 entry 답습)로 1회 이상 구동 가능함을 MVP 단계 evidence로. 이것이 5조-2 제3항의 ① 레이어 적용 형태다.

나머지 3 invariant: **헌법 8조** — (R)이 새 평문 저장 경로를 만들지 않는 한 보존(단 ① 레이어 Claude가 프라이데이 R1 관찰 데이터를 자비스 프로젝트 메모리/세션 로그에 남기면 R-Friday-4 우회 — §4 참조). **ADR-011 §2.4 T3** — 자비스 스코프에선 보존, 프라이데이 내부 tier는 §6 참조. **Boss ≠ root of trust** — (R)에서 새 위험: "Claude(①)가 프라이데이를 키운다"가 "Claude 출력 = 신뢰"로 미끄러지면 안 된다. ① 레이어 출력(프라이데이 코드·정책)도 권위 위계상 검증 대상이며, 진화 주기마다 계산적 센서(테스트/린트/canary)가 위에 있어야 함을 명문 권고.

### 5. Rollback Trigger 충분성

R-Friday-1~5는 침범·HW·invariant·R1·비용 5축을 커버하나 전원 **사후 검출**이고, (R) 도입으로 생긴 축이 빠졌다. 추가 권고:

- **R-Friday-6 (신규): ① 레이어 루프 폭주** — `/loop` self-paced 주기가 무감독 반복으로 토큰/rate limit 소진 → 자비스(동일 구독) 작업 차단. trigger 예: 무인 진화 주기 N회 연속 또는 자비스 세션 rate-limit 차단 1건. R-Friday-2(HW)와 별개 축.
- **R-Friday-7 (신규): 격리 정의 약화 시도** — 프라이데이 cycle diff에 자기 격리 정책(Landlock/ACL/audit 설정) 완화가 포함되면 즉시 발화. R-Friday-1(자비스 파일 변경 = 침범 *후*)의 사전 단계 센서.
- **R-Friday-8 (신규, ADR-011 R-6 동형): upstream 변경 회귀** — `/loop`·Workflow는 Anthropic 통제 기능. Claude Code 업그레이드 시 진화 루프·격리 동작 재검증 의무 (Hermes 업그레이드 자동 R-2 재실행 패턴의 정확한 유비).
- R-Friday-4의 "10MB 누적"은 관대하나 "민감 정보 1건 OR" 축이 있어 개인 툴 비례성상 수용 가능 — 유지.
- R-Friday-1~5의 **검출 주체 미명시** 공통 결함: trigger는 등록됐지만 *누가/무엇이* 감시하는지(hook? CI? 사람?)가 없다. 센서 없는 trigger = 권고문. MVP-0에서 trigger별 센서 바인딩 의무.

### 6. T1/T2/T3 정합

- **자비스 스코프**: brief §1.2 4·§3.3·§4.7이 T3(헌법/ADR/게이트 변경 자동 금지)를 보존하고, "프라이데이 학습 결과의 자비스 본문 *제안*도 금지"는 ADR-011 §2.3 운영 함의 #5(학습 결과 자동 정책 반영 금지)보다 엄격 — 정합.
- **프라이데이 내부 스코프 = 미정의 위험**: "Layer 3 자동 적용 자격 (격리 안)"(§2.1)이 "격리 안에서는 T3도 자동"으로 해석될 여지가 있다. 이 해석이면 프라이데이가 자기 harness gate(격리 정의·rollback trigger 정의 포함)까지 자동 변경 → B-4 경로 합법화. **프라이데이 내부에도 "T3-core"(① 격리 정의 ② R-Friday trigger 정의 ③ 자비스 접근 정책 ④ 권위 분리 명문)는 자동 변경 절대 금지 영역으로 명문**해야 한다. 자동 진화 허용 범위 = 프라이데이의 T1(학습 누적)+격리 안 T2 상당(자기 코드/프롬프트)까지, T3-core 제외.
- **① 레이어의 tier 미분류**: `/loop` 각 주기의 산출물 적용(코드 커밋)이 T1인지 T2인지 분류가 없다. 격리 안 실험이므로 헌법 위반은 아니나, MVP-0 설계 brief에서 프라이데이용 tier 매핑표를 선결 산출물로 요구.
