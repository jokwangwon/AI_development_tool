## Agent C 대안 탐색 보고서

### 1. 종합 판정: **CONDITIONAL-PASS**

(R) 하이브리드 방향 자체는 (P)/(Q) 대비 우월하며 유지 권고. 단, ① **진화 대상·적합도 함수(fitness function) 미정의**, ② **격리 5-layer 중 일부의 과설계**(별도 repo 채택 시 구조적으로 해소 가능한 부분을 게이트로 방어), ③ **stale gate 수치**(144 tests 하드코딩) — 이 3가지를 MVP-0 설계 brief에서 해소하는 조건부 통과.

### 2. 핵심 발견

1. **(Q) Hermes 도입은 부분적 허상 옵션이다.** ADR-008은 "Design Adoption only, PMO 격상 0건" — 즉 도입 가능한 *실행 프레임워크*가 존재하지 않고 설계 문서만 존재한다. (Q)를 선택해도 실제로는 (P) 자체 구현 + Hermes 설계 답습이 되므로, D-2에서 (Q)가 이미 배제된 것은 정당하다. (R)은 사실상 "(P)의 구현 부담을 Claude 루프 하네스로 상쇄"한 형태로, 유일하게 현실적인 후보였다.
2. **(R)의 숨은 긴장: 진화 엔진 계층의 Provider Liquidity.** brief는 "런타임 두뇌=로컬이라 Provider Liquidity 보존"이라 하지만, **성장 과정 자체는 Claude Code `/loop`+Workflow에 종속**된다. 헌법 5조-2(모델/구독/오케스트레이터 교체 가능, 비협상)를 문자 그대로 적용하면 부모 계층도 대상이다. 완화책: 진화 루프의 정의(관찰→변이 제안→검증→적용 절차)를 **provider-중립 스펙 문서**로 두고 Claude는 그 스펙의 *실행자*로 위치시키면 해소된다. MVP-0에서 명문화 권고.
3. **진화 대상이 brief 전체에서 한 번도 정의되지 않았다.** "Layer 3 자동 적용 자격"이라고만 하고 *무엇을* 자동 적용하는지(코드? 프롬프트? 정책? 도구?) 부재. 더 치명적으로 **적합도 함수(무엇이 "개선"인지 판정하는 계산적 센서)가 없다**. 센서 없는 자가진화는 방향 없는 자가변형일 뿐이다.
4. **격리 5-layer 중 2개는 D-3=(b) 별도 repo 선택 시 공짜로 해소된다.** brief 권고 (a) 같은 repo 별도 브랜치는 branch protection rule 신설 의무(센서 방어)가 따라오는 반면, (b) 별도 repo는 코드 격리+commit 격리를 **구조적으로**(feedforward) 보장한다 — "잘못하는 것이 불가능하게 만들어라"(CLAUDE.md §2) 원칙에 정확히 부합. 게다가 홈 디렉토리 실측: `~/gen_gate`, `~/motion_lab`, `~/style_forge` 등 **이 생태계의 확립된 패턴이 이미 12개 별도 repo**다. 자비스 repo 안 브랜치가 오히려 생태계 이례.
5. **재사용 가능 자산 3건이 brief에 미반영.** ① 자비스 Layer 0 JSONL 관찰 + Layer 1 `PatternReport`(`src/jarvis/layer1.py` — frozen, read-only, 보고만) = 프라이데이 첫 진화 원료로 즉시 소비 가능. ② `~/.gb10/gpu_lock.py` cross-process flock 규약 = D-5 "idle 시점만"이라는 *수동 정책* 대신 *계산적 강제*로 대체 가능. ③ `src/adapters/llm/redaction.py` = R-Friday-4의 SQLCipher 대신 경량 대안.
6. **stage gate 조건이 시대에 뒤처졌다.** brief(2026-05-27)의 "144/144 tests"는 현재 자비스 실태(제어측 거의 완성, PR #55 MERGED, 테스트 수 대폭 증가)와 불일치. E-Friday-3의 "144" 하드코딩은 "풀 스위트 green"으로 교체 필요. §5.1 carry-over 체크리스트(b1-AR3 등)도 상당수 이미 소화되었을 가능성 — 진입 자격 재베이스라인 필요.
7. **"관찰→제안만" 최소 실험 단계는 이미 자비스가 끝냈다.** Layer 0/1이 정확히 그 단계(보고만, 적용 0)를 발효·실증했으므로, 프라이데이 MVP-0에서 propose-only 단계를 반복하는 것은 중복이다. 프라이데이의 *차별적* 최소 실험은 "가장 좁은 표면에서의 자동 적용 + 자동 revert"다.

### 4. 과설계/비례성 진단

| 항목 | 진단 | 권고 |
|---|---|---|
| 5-layer 격리 | **부분 과설계** — 별도 repo(D-3=b) 선택 시 코드+commit 격리는 구조적으로 소멸, 메모리 격리도 별도 프로젝트 디렉토리로 자동 해소(D-4 소멸) | 5-layer → 실질 2-layer(endpoint + filesystem ACL)로 축소. 안전 결과 동등 이상 (구조 격리 > 게이트 격리) |
| R-Friday-1 | 별도 repo면 거의 발생 불가 — 유지하되 비용 0 센서(자비스 repo git diff)로 강등 | 유지 (비용 0) |
| R-Friday-2 (HW/OOM) | **실질 위험 맞음** — 신규 설계 대신 기존 `~/.gb10/gpu_lock.py` flock 동참으로 해소 | 재사용으로 경량화 |
| R-Friday-3 "제안 포함" trigger | **과잉** — 사용자에게 도달하는 *제안*은 침범이 아니라 학습 가치의 산출물. 제안=ROLLBACK이면 프라이데이 존재 이유와 충돌 | "자동 적용 시도"만 ROLLBACK, "제안"은 기록+표시로 강등 |
| R-Friday-4 SQLCipher | **과잉** — solo 개인 실험 툴에 암호화 저장소는 비례 보안 전형적 DEFER 대상 | 기존 `redaction.py` 재사용 + 10MB 상한 유지. SQLCipher = DEFER |
| R-Friday-5 | 적정 — 이산 cycle 채택 시 자연 통제 | 유지 |
| 풀 3+1 + 외부 LLM 1+ | **진입 합의 1회는 적정**. 단 이후 매번 풀 합의면 ceremony 인플레이션 | 풀 합의 = 이번 1회 + T3-인접 결정만. MVP-0 설계는 1-agent + Reviewer 상한 |

**총평**: 방어 총량은 유지하되 *수단*을 「게이트→구조」로 치환하면 문서·운영 부담이 절반 이하로 줄고 안전 결과는 동등 이상. ADR-011 §2.1 (a) 조건("동등 이상 안전 결과")의 정공법 충족.

### 5. 자가진화 대상 명확성 평가 + 대안

**평가: 불명확 (brief의 최대 갭).** "무엇이 개선인가"를 판정할 계산적 센서(적합도 함수)가 없으면 자동 적용은 자동 훼손과 구별 불가능하다.

**대안 — MVP-0 진화 대상 사다리 (위험 오름차순, ADR-011 T-tier 정렬)**:

| 단계 | 진화 대상 | T-tier | 적합도 센서 (계산적) | 근거 |
|---|---|---|---|---|
| **F-0 (MVP-0 권고)** | 프라이데이 자신의 **프롬프트/설정** | T1 인접 | **고정 벤치마크 태스크 스위트 점수** — `model_benchmark.py` 계보 재사용. 변이 적용→재측정→점수 하락 시 자동 revert | 최소 위험 표면 + 즉시 가역 |
| F-1 | 자신의 **도구/스킬 정의** | T2 성격 | 도구 사용 성공률 (Layer 0 식 JSONL 관찰) | 사용자 승인 개입 지점 자연 발생 |
| F-2 | 자신의 **코드** | Layer 3 본령 | 자기 테스트 스위트 green + 벤치마크 비하락 | 존재 이유의 완결 |
| 영구 제외 | 자비스 본문·헌법·ADR (T3) | — | — | R-Friday-3 |

**진화 원료 대안**: 첫 관찰 데이터를 0에서 모으지 말고 자비스 Layer 0 JSONL + Layer 1 `PatternReport`(frozen, read-only API)를 **읽기 전용 소비**로 부트스트랩 — "자비스는 관찰까지, 프라이데이는 그 관찰의 소비부터"라는 깨끗한 분업이며 침범 0.

### 6. 단계적 진입 대안

**"관찰→제안만"부터 시작하지 말 것** — 그 단계는 자비스 Layer 0/1이 이미 발효·실증했다. 권고 시퀀스:

```
F-0a (1 cycle): 뼈대 — 별도 repo + 별도 Ollama endpoint
               + 고정 벤치마크 스위트 + gpu_flock 동참. 진화 0.
F-0b (1-2 cycle): 최소 진화 루프 1바퀴 — Claude 이산 cycle이
               프롬프트 변이 N개 fan-out 생성 → 벤치마크 자동 측정
               → 최고점 자동 적용 → 하락 시 자동 revert.
               ← "Layer 3 자동 적용"의 최소 실증 (b) PoC evidence
F-1+: 대상 사다리 상승 (도구 → 코드). 각 단계 진입 = 사용자 명시.
```

핵심: **F-0b 한 바퀴가 ADR-011 §2.1 (b)(격리 PoC 실증)와 (d)(자동 회귀 검증)를 동시에 산출** — 진입 자격 매트릭스 잔여 3/5 중 2개를 최소 비용으로 채우는 경로.
