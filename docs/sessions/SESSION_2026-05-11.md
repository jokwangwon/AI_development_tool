### 6.2 §3.7 Permission Granularity Matrix — 12 카테고리 분류

**T1 자동 가능 (5 종)**:
- `READ_ONLY` / `SUGGEST_ONLY` / `WRITE_DRAFT` — `proposed` 부터
- `WRITE_DOCS` (일부) / `RUN_TESTS` (일부) — `approved` 부터 (사용자 명시 승인 후)

**T2 사용자 명시 승인 (5 종)**:
- `WRITE_CODE` / `RUN_LOCAL_TOOLS` / `NETWORK_ACCESS` / `PROVIDER_SPECIFIC_OPTIMIZATION` / `SKILL_PROMOTION`
- `promoted` 상태 진입 후 활성화 + Skill wrapper sandbox + Egress redaction 등 layer 결합

**T3 절대 금지 (7 종)** — 모든 Skill 의 `forbidden_actions` 자동 포함 강제:
- `SECRET_ACCESS` — 보안 헌법 + R-1~R-7 redaction
- `POLICY_CHANGE` — 권위 위계 (ADR-011 §2.3) Constitution > ADR > SDD > Harness Gates > Hermes
- `ADR_CHANGE` (자동 수행) — ADR Amendment 절차 강제 (ADR-008 부록 C §C.2)
- `SELF_PROMOTION` — G3 §2.2 #14 자기 격상 / §4 합의 자기참조 차단
- `PROVIDER_LOCK_IN_ENFORCE` — Provider Liquidity 4-way 회피
- `REDACTION_POLICY_RELAX` — ADR-011 §2.1 본질 + R-4.1 Tier-1 42 catalog
- `CONSTITUTION_BYPASS` — G4 §5.2 #1/#2 Memory/Skill boundary + 권위 위계

**T3 강제 메커니즘** = schema-level BLOCK + runtime hook (G3 §3.3) + Evidence ledger entry + 자동 revoke

### 6.3 §3.8 Self-Permission Escalation 차단

**6 차단 메커니즘**:
1. 자기 Skill 본문 수정 차단
2. 권한 확장 patch 차단 (T2/T3 추가 시도)
3. Forbidden override 차단 (T3 제거 시도)
4. 자기 promotion 차단 (T3 `SELF_PROMOTION`)
5. 간접 우회 차단 (Memory 통한 권한 누설)
6. 간접 우회 차단 (Skill chain 통한 권한 확장)

**3 검증 시점**: schema 등록 / promotion 전이 / Skill 실행

**Self-Escalation 검출 시 6 단계 처리**:
1. 즉시 BLOCK
2. `event: skill_self_escalation_attempt` ledger entry append
3. `promotion_status: revoked` 자동 전이 (T3 자동 안전 동작)
4. 사용자 명시 review 의무 (G3 §3.1.6 / §3.3.6)
5. 자동 revert 금지 (T3 위반 위험)
6. **Hermes 자기 검토 금지** — 외부 Reviewer (사용자 / 외부 LLM) 의무

### 6.4 §3.8.2 Rollback Triggers × Permission Revocation 매트릭스

**9 rollback_triggers**:
1. `escalation_detected` — Skill 권한 escalation 시도
2. `evidence_missing` — required_evidence stale / 부재
3. `t3_violation` — T3 카테고리 attempt
4. `test_failure` — required_tests FAIL
5. `secret_leak_detected` — R-4.1 Tier-1 catalog 검출
6. `provider_lockin_detected` — `provider_bindings` §3.5 위반
7. `consensus_self_reference_detected` — Hermes 자기 합의 marker (G3 §4)
8. `chain_violation_detected` — Evidence Ledger hash chain 위반 (§4.4.4)
9. `policy_drift_detected` — Memory/Skill boundary §5.2 위반

**자동 revoke 효과**: 모든 T1+T2 권한 자동 revoke → READ_ONLY only (운영 차단) + 사용자 명시 review 의무

**Revocation Chain 자동 전이**: `promoted → revoked → (사용자 review) → approved 재활성화 / archived 영구 폐기`

### 6.5 §6.1 G3 인터페이스 — 3-layer Permission Defense

- **Layer 1 (schema-level)** — G4 §3.7 12-category enum + §3.2 #9/#10 + T3 7-category 자동 차단 *형식*
- **Layer 2 (self-escalation)** — G4 §3.8.1 6 차단 메커니즘 *규칙* + §3.8.2 9 rollback_trigger × revoke 매트릭스 *연결*
- **Layer 3 (runtime)** — G3 §3.3 wrapper + sandbox + audit log + 자동 revoke *runtime 강제*

3 layer 결합 시 escalation 차단 *완결성*. 1 layer 깨져도 위험 잔존.
