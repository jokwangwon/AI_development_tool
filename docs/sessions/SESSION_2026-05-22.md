### A1 핵심 발견 (E2E 실측)
- ⭐ **claude `-p`는 홈 통째 RO 필요**: `claude --version`은 시스템 경로만으로 격리 동작하나, `-p` 실행은 홈 의존(설정·캐시·런타임)이 커서 `~` 전체 RO 노출 필요. 부족하면 출력 0으로 **hang**(/ 전체 RO 시 동작 → fs 경로 부족 확진). 쓰기는 workdir(RW)만 — 그 외 커널 차단.
- ⭐ **cwd·TMPDIR = workdir 필수**: `ll_sandbox`는 cwd 미변경 → runner가 `cwd=workdir` + `TMPDIR=workdir` 설정(CliWorker 기본 runner가 cwd=workdir 하므로 정합). 안 하면 claude가 "writable location?" 반문.
- **RO 정밀화(민감 파일 읽기 차단)는 워커별 후속 과제** — claude=넓은 RO, codex/단순 워커=좁은 RO. `LandlockIsolation.ro_paths` 워커별 조정이 설계 강점. net egress(B1)와 함께 후속.
- **이로써 MVP-0 = 실동작 완료** (코드·테스트·실 워커 E2E 전부 통과).

### B1 핵심 발견
- ⭐ **무권한 환경엔 *호스트 단위* egress allow-list 강제 수단 부재** (V-2 fs 격리와 평행 구조 — 무권한에서 강한 수단 제한). netns/nft=권한 전제, Landlock net=포트만, proxy/DNS=우회.
- ⭐ **means/ends**: egress 차단=MEANS. 클라우드 워커→provider egress는 §0 B-3가 인정한 *수용된* 흐름이라 차단 대상 아님. "추가 유출" 강제 차단의 한계이득이 무권한 수단으론 작고 M4(root)는 비례 초과 → DEFER. 실 trigger(팀/공유/민감) 시 발효(credential 패턴).
- 코드 0건(DEFER). 청사진(brief §1~§7) 보존.
