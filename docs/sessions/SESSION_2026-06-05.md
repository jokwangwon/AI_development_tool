### ⭐ 합의 핵심 (A·B·C 독립 수렴)

- **CB-2 누적 영속 = LedgerLog 파생**: in-memory면 controller 재시작이 누적 한도를 리셋(우회) → ledger read() 파생.
- CB-3 Launcher(non-blocking Popen+setsid/killpg) · CB-4 감사 fail-closed · CB-5 lock atomicity · CB-6 seam 토큰 강제 · CB-7 adopt=cutover · CB-8 dangling 회부 · CB-9 동시1 우선순위.

### 풀 3+1 합의 (REVISE) — ⭐ 적대적 검증이 결함 포착
- **rate=R-b(5/60s)**: A·B·C 3개 독립 수렴.
- **누적 축 적대적 검증**: Agent C 제3안 **2-B(누적을 crash-loop 탐지로 *재정의*)**가 **CB-2를 깸** — 누적이 *성공* op를 안 세면, controller 재시작으로 in-memory rate 리셋 → 무제한 성공 lifecycle 경로 재개방. → **대체 REJECT**(탐지 아이디어는 추가 센서 후속으로 유효). C-b(windowed)는 새 우회 표면 3개(시계 후퇴·fixed-window burst·ts 무결성)로 후속.
- **누적=C-a(값↑)** 권고. **값 확정=사용자**: rate 5/60s, 누적 lifetime 100.
- BLOCKING **CC-1**(CB-2 기능 보존=누적은 executed 셈)·CC-2(L-5 2축)·CC-3(경계 불변)·CC-4(windowed 시 안전)·CC-5(rate=executed 빈도 명시).
