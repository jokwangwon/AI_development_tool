### ⭐ 합의 핵심 (A·B·C 독립 수렴)
- **CB-1 PID recycling 차단**: 소유권 키 `(pid, starttime)`, signal 직전 재대조 — OS가 같은 PID를 다른 프로세스에 재할당 시 엉뚱한 것 죽이는 함정(pkill 금지의 더 깊은 버전).
- **CB-2 누적 영속 = LedgerLog 파생**: in-memory면 controller 재시작이 누적 한도를 리셋(우회) → ledger read() 파생.
- CB-3 Launcher(non-blocking Popen+setsid/killpg) · CB-4 감사 fail-closed · CB-5 lock atomicity · CB-6 seam 토큰 강제 · CB-7 adopt=cutover · CB-8 dangling 회부 · CB-9 동시1 우선순위.

### 산출
| 항목 | 핵심 |
|------|------|
| `src/jarvis/launcher.py`(신규 leaf) | `spawn`(non-blocking Popen+start_new_session) / `signal`(os.killpg 그룹종료, **자기그룹 자살 가드**) / `find_listener_pid`(/proc/net/tcp inode→pid) / `read_starttime`(/proc stat) |
| `process_control.py` 확장 | start/stop/restart(MEDIUM)+adopt(HIGH 새 capability) · `_decide` MEDIUM 분기(lock critical section) · `(pid,starttime)` 소유권 · C-3 2축+rate · seam 토큰(`SeamViolation`) · cutover · 포트 해제 대기 |

### 진단 (단계적 좁힘)
1. "열어둔 채 안 바뀜" → 모달에 새로고침 버튼 부재 → 🔄 추가 + fetch no-store.
2. 사용자 "새 측정해도 5/29 그대로" → **근본 진단**: 측정 JSON·DB 모두 5/29 마지막. `migrate_legacy`=bootstrap-once(kind 가드)라 JSON 갱신 무시 + ⭐ **측정을 *수행*하는 도구가 repo에 0**(저장 인프라 append_measurement·measurement:write는 존재했으나 호출처 없음). 5/29=v0.0 legacy. ollama 모델도 llama3.3/exaone4→qwen3 계열 교체로 랭킹 불일치.
3. 사용자 "측정 따로 안 함" → "갱신 안 됨"은 버그가 아니라 **측정 수단 부재** → 측정 실행 기능 신설 결정(사용자: 모달 선택·n_runs=3).

### 산출
| 항목 | 핵심 |
|------|------|
| `src/jarvis/model_benchmark.py`(신규 leaf) | `run_benchmark` = 모델별 warmup + n_runs회 ollama `/api/generate` → `metrics_from_response`(decode/prefill tok/s·latency) + `compute_stats`(mean/p50/std/min/max). 출력 = `append_session(kind="multi")` 입력과 정확 일치. `generate_fn` 주입 hermetic. 실패=skipped/error run(fail-soft) |
