### 흐름
1. **brief**(`jarvis-output-application-loop-brief.md`) → 사용자 검토 → **방향 고정**:
   첫 슬라이스=slice-app-1 권고안 / 대상=등록 외부 repo만 / commit 정책=apply만(사람 commit).

3. TDD → server 배선 → UI(mockup 컨펌) → 실 git e2e → 헤드리스 육안.

### ⭐ 합의 핵심 — 적대적 검증이 brief 누락 포착
- **CB-1(CRITICAL)**: `git apply --check`는 **문법만 검증, 의미는 검증 안 함**. plugin_install
  C-3는 출발점(workdir)만 봄 → **도착점(patch가 repo에 뭘 하는가) 검증 모듈 신규 필수**.
- BLOCKING 7: CB-1 patch_validator · CB-2 화이트리스트(쓰기 0) · CB-3 fail-closed(3-way 금지)
  · CB-4 repo clean · CB-5 preview scrub · CB-6 자동반영 금지(same-origin+confirmed) · CB-7 apply≠commit.
- Q-b=fail-closed(만장일치) / Q-d=workdir 전체 diff(B 명시목록안 V-1 DEFER, 우려는 BLOCKING 흡수).
