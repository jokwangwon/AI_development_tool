## ② 만화 생성 시스템 dogfooding — 자비스 북극성(일반 명령 실행 에이전트) 실증

> 사용자 의도: 프로젝트를 "자비스로 바로 작성하듯이" 만들어 **자연어 명령 → 이해 → 정리
> (노트/도식) → 개발**까지 실제로 가는지 검증. 구동 = 내가 API(`/api/respond`·`/api/jarvis/plan`)로.

④캐릭터 페르소나 대사 생성기. **합의 방향**: 첫 슬라이스=텍스트 파이프(③줄거리→④대사),
이미지=로컬 GPU 별도 서비스(**Anima 모델** 추천, 나중). 모듈 간 **JSON 계약**(panels 중심,
캐릭터 persona 단일 출처=③).

### 자비스 능력 실측
- `/api/respond` mode=auto/note/svg/chat — 노트·도식화·자연어이해·개발 라우팅 **전부 실재**.
- note ✅(제목+태그+본문, 다소 얕음) · svg ✅(유효 SVG 4박스+화살표, 레이아웃 엉성) ·

### 자연어 → 개발 경로의 연쇄 마찰(핵심 학습)
| 시도 | 설정 | 결과 |
|------|------|------|
| 1 | 큰 명령(2단계+테스트) | **step limit 초과 6>5** (정상 안전 가드) |
| 2 | 좁힌 명령(줄거리 생성기만) | **8>5** — 좁혔는데 오히려 증가 = boss 비결정 분해(갭3) |
| 3 | +coder-next planner, **opts 중첩**(내 실수) | worker_kind 거부 — real_workers 미적용(payload 형식 오류) |
| 4 | **flat payload**, real_workers | allow_code_consume opt-in 필요(2차 injection 방어 게이트) |
| 5 | +allow_code_consume(사용자 승인) | ✅ **plan 통과 → awaiting**(단일 subtask, consume 없음) |

- **정정**: 시도3 worker_kind 실패 = 내 API payload 실수(`{opts:{real_workers}}` 중첩 →
  서버는 flat 기대, `jarvis_plan.py:312` create_plan(data)). 자비스 갭 아님. 시도1·2 step
  수도 real_workers 미적용(file-only planner) 상태라 정확한 재현 아니었음.
- step limit(5)=`plan_controller.py:45` 의도된 안전 가드(폭주·검토부하 상한). worker_kind·
  allow_code_consume 게이트 = 모두 정상 작동(2차 injection 방어 §48-50).
