## ① 딥리서치 1R — 토킹헤드 landscape (101 agents, 22 검증/3 기각)

- ⭐ **실사 토킹헤드 전부 anime 구조적 부적합**: SadTalker·MuseTalk·AniPortrait·Sonic·EchoMimic·
  Hallo 모두 실사 얼굴(3DMM·landmark·insightface) 전용. SadTalker 공식 "only works on REAL people".
- **THA3(talking-head-anime-3)가 anime 유일 적합**: 512² 알파 1캐릭터, 45-dim 포즈. but pose 구동
  (오디오 아님) → audio→viseme 브리지 필요.
- HW 리스크(지배적): GB10=sm_121 aarch64. torch aarch64 CUDA는 2.11+ 부터(GB200 검증, GB10 미확인),
  onnxruntime-gpu aarch64 PyPI 휠 없음 → insightface/onnxruntime 의존 실사 모델들 깨지기 쉬움.
  THA3는 이 의존 0 이라 HW가 THA3 지지. 라이선스 양호(MIT/Apache 계열).

## ② 딥리서치 2R — 결정점 2개 (96 agents, 23 검증/2 기각)

- **audio→pose 브리지 기성품 없음**: THA3/THA4/SillyTavern 전부 pose 구동. Rhubarb·OVR는
  audio→viseme만, THA3 45-dim 출력 안 함 → 매핑 자작. 한국어 약함(Rhubarb 영어, OVR x86).
- **Live2D vs THA3 = CPU vs GPU**: Live2D=결정적 CPU(GB10 리스크 회피) but 캐릭터별 리깅 노동.
  Inochi2D=BSD. THA3=리깅0 but GPU. 기각: "Live2D 1천만엔 등급"(1-2), "립싱크 진폭뿐"(0-3).

## ③ THA3 GB10 PoC — 지배 리스크 사망 (`~/motion_lab/poc_headless.py`)

- 환경 실측: GB10 sm_121, CUDA 13.0, torch **2.12.0+cu130** 이미 설치·실 matmul 커널 작동.
- ⭐ **THA3 헤드리스 구동**: 로드 1.4s · **~33ms/frame ≈ 30fps** · GPU **1.8GB** · insightface/
  onnxruntime/3DMM 의존 0. num_params=45, `mouth_aaa(26)/iii/uuu/eee/ooo(30)` 모음 viseme 직접 노출.
- **시각 확인**: closed→aaa(입 크게)→ooo(둥글게) 입모양 실제 변화, 캐릭터·화질 보존.
- → 2R 우려 2리스크(sm_121 GPU·viseme 자작) **둘 다 무너짐**. Live2D CPU 우위 무의미화.

## ④ 브리지 PoC — 전체 루프 닫힘 (`~/motion_lab/poc_bridge.py`, `talking_clip.mp4`)

- 실 WAV(voice_lab 한국어 6.5s) → RMS+LPC 포먼트 F1/F2 모음분류 → viseme 트랙(195프레임,
  발화118/무음77) → THA3 렌더 → ffmpeg 음성합성 **mp4**. ⭐ **음성→움직이는 입→동기 mp4 전부 로컬**.
- 무음=입닫힘 작동, 발화중 입모양 변화 시각확인. 렌더 ~18fps(알파합성 포함).
- **정직한 한계**: LPC 포먼트 모음분류 편향(iii=71 과다·ooo=0) → 프로덕션엔 음소정렬기 필요. PoC 품질.
