## ④ 스파이크 3 — TRELLIS.2 (Microsoft, MIT) ⭐ 최종 채택

- **TRELLIS.2-4B = MIT(코드+가중치, 영토제한 없음) + 풀 PBR GLB + SOTA**. dense 어텐션은 sdpa 지원, sparse는 flash_attn varlen 전용.
- **GB10 빌드 전부 성공**: **flash-attn 2.8.3**(`TORCH_CUDA_ARCH_LIST="12.0"` → sm_121 네이티브, varlen 커널 실행 검증) + 커스텀 커널 5종(nvdiffrast/nvdiffrec/CuMesh/FlexGEMM/o-voxel; o-voxel은 CuMesh의 Eigen 헤더 복사로 해결).
- **런 패치 2건** (`/tmp/trellis_run.py`, ⚠️ /tmp 휘발 → 다음 세션 영속화 필요):
  1. **rembg 교체** — 4B config 기본 rembg = `briaai/RMBG-2.0`(게이트+**non-commercial** 라이선스 함정!) → `ZhengPeng7/BiRefNet`(MIT, ungated) monkeypatch.
  2. **DINOv3 layer 경로** — transformers 5.12에선 `model.model.layer`(DINOv3ViTEncoder 하위), TRELLIS는 `model.layer` 기대 → `extract_features` monkeypatch(forward 시그니처는 전부 일치).
- **게이트**: DINOv3(`facebook/dinov3-vitl16-pretrain-lvd1689m`)는 HF 게이트(Meta 수동 승인). **사용자가 `kwon12` 계정으로 동의→승인 완료**. DINOv3 라이선스 = commercial + **worldwide(한국 OK)** + "Built with DINOv3" 표기 의무(영토/MAU 제한 없음).
- ✅ **e2e 성공**: firefly.png → `~/3d_lab/firefly_trellis.glb` (40MB, **762k verts/969k faces, PBRMaterial = baseColor 4096² + metallicRoughness 4096²**). load 121s+gen 280s+glb 91s ≈ 8분. 360° 일관 고품질(렌더 `/tmp/trellis_firefly_4views.png`). **char_factory 5.2 blob 결정적 돌파.**

## ⑤ ⚠️ 서버 크래시 2회 원인규명 + 방어 (중요 운영 교훈)

- 세션 중 서버 2회 다운. 원인 = **flash-attn `MAX_JOBS=8` 컴파일 OOM** — nvcc가 커널당 8~15GB RAM 폭식 → 8잡 = 80~100GB+ 피크 → 121GB 통합메모리 고갈 → 커널 패닉/재부팅. (메모리 기록의 ollama-GPU OOM과 **별개의 컴파일-RAM OOM 모드**.)
- **방어(적용·검증)**: 무거운 CUDA 빌드는 **`MAX_JOBS=2`(피크 ~24GB) + 메모리 워치독**(15s마다 가용 로깅, <12GB면 빌드 자동 중단). 이후 flash-attn 빌드 무사 통과(최저 가용 60GB+). 메모리 `reference_gb10_unified_memory_oom` 2차 모드로 기록.
