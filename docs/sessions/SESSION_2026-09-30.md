# SESSION 2026-09-30 — GitHub README 정리

## 요청과 변경

- 사용자 요청에 따라 공개 코드와 커밋 이력을 먼저 점검하고 README를 검증 가능한 개발 프로세스 중심으로 재작성했다.
- 승인·워커·결과 검토·작업 기록·격리 어댑터·테스트에 직접 연결했다. 설계 목표와 실제 기능을 구분하고 Experimental 상태를 명시했다.
- main/develop 양쪽에서 확인되는 핵심 기능을 설명했다. 미공개 로컬 코드나 다른 프로젝트의 구현은 포함하지 않았다.
- 애플리케이션·검증 정책·CI·보안 경계 코드는 변경하지 않았다.

## Git와 검증

- origin/develop에서 feature/github-readme-positioning을 분기했다. PR 대상은 develop이며 main 릴리스는 별도 결정에 따른다.
- README 상대 링크와 git diff --check를 확인했다. 기존 커밋 검사와 PR 검사를 적용한다.
- Jarvis CI의 단위 테스트·sandbox 컴파일 범위와 환경 의존 런타임 통합 검증의 차이를 명시했다.
- 기존 bin/setup.sh 실행은 core.hooksPath와 pre-commit install의 충돌로 중단됐다. README의 테스트 준비 절차를 의존성 설치로 분리하고 설치 제약을 명시했다.
- 문서 작업용 임시 clone에서는 기존 Layer 3 hook을 pre-commit의 legacy hook으로 연결해 두 검사가 모두 실행되도록 로컬 Git 설정만 조정한다. 추적되는 hook·검사 정책은 변경하지 않는다.
- 실제 검증: 설치 audit 3개 항목 통과, 기존 pre-commit 검사 6개 통과, approval/review/ledger 테스트 29개 통과. 전체 런타임 통합 테스트 재실행 결과는 아니다.
